# LLVM IR 실습 가이드

지금까지는 소스 코드를 해석해서 AST를 만들고, AST를 순회하며 프로그램을 실행했다.
이번에는 LLVM IR을 직접 작성해서 실행 파일로 만들어 본다.

LLVM IR은 특정 CPU의 어셈블리는 아니지만, 계산과 메모리 접근, 실행 흐름을 명령 단위로 작성할 수 있다.
수식, 변수, 조건문, 반복문, 함수가 더 작은 명령으로 어떻게 구성되는지 직접 확인하는 것이 목표다.

AI의 도움을 받으면서 프로그래밍할 땐, 최소한의 IR로 프로그래밍하는 상황임을 설명하고, phi를 도입하지 말라고 이야기해야 한다. (추후 여유가 된다면 설명)

## 실습 준비

1. `clang --version`으로 설치 여부를 확인한다. 이 가이드는 LLVM/Clang 15 이상을 기준으로 한다.
2. 코드는 텍스트 형태의 LLVM IR인 `.ll` 파일로 작성한다.
3. 정수는 `i32`로 통일하고, 나눗셈과 크기 비교는 부호 있는 정수 기준으로 처리한다.
4. `;`으로 시작하는 줄은 주석이다. 컴파일러가 무시한다.

```sh
clang 파일명.ll -o 출력파일 && ./출력파일
```

## 입출력 함수

두 번째 실습부터 아래 함수들을 사용한다. 매 파일마다 포함시켜야 한다.

```llvm
declare i32 @printf(ptr, ...)
declare i32 @scanf(ptr, ...)

@.rfmt = private constant [3 x i8]  c"%d\00"
@.wfmt = private constant [4 x i8]  c"%d\0A\00"

define i32 @read() {
  %buf = alloca i32
  call i32 (ptr, ...) @scanf(ptr @.rfmt, ptr %buf)
  %val = load i32, ptr %buf
  ret i32 %val
}

define void @write(i32 %n) {
  call i32 (ptr, ...) @printf(ptr @.wfmt, i32 %n)
  ret void
}
```

- `@read`는 정수 하나를 읽어 반환한다.
- `@write`는 정수 하나를 출력하고 줄바꿈한다.

## 실행 확인

`.ll` 파일을 컴파일해서 실행 파일로 만들 수 있음을 확인한다.
입출력 함수 없이 작성하는 유일한 실습이다.

LLVM IR 프로그램은 `@main` 함수에서 시작한다.
`ret i32 0`은 프로그램을 종료하고 종료 코드 `0`을 반환한다.

```llvm
define i32 @main() {
  ret i32 0
}
```

```sh
clang hello.ll -o hello && ./hello
echo $?
```

### 구현 과제 #1

1. 위 코드를 컴파일하고 실행한다.
2. `echo $?`로 종료 코드를 확인한다. `0`이 출력되면 성공이다.
3. `ret i32 0`을 `ret i32 42`로 바꾸고 종료 코드도 `42`로 바뀌는지 확인한다.

### 알아 둘 내용

1. `@`는 함수와 전역 이름에, `%`는 함수 안의 값과 블록을 참조할 때 사용한다.
2. `define`은 함수의 구현이다. 이 프로그램은 `@main`부터 실행한다.
3. `ret`은 현재 함수의 실행을 끝내고 반환한다.

## Echo

숫자를 하나 읽어 그대로 출력한다. 이 실습에서 처음 사용하는 명령들이다.

| 명령 | 역할 |
|------|------|
| `call void @write(i32 %n)` | 반환값이 없는 함수를 호출한다 |
| `%v = call i32 @read()` | 함수를 호출하고 반환값을 `%v`에 받는다 |
| `%x = alloca i32` | 스택에 32비트 정수 공간을 할당하고 그 주소를 `%x`에 저장 |
| `store i32 %v, ptr %x` | `%x`가 가리키는 주소에 `%v`를 씀 |
| `load i32, ptr %x` | `%x`가 가리키는 주소에서 값을 읽음 |

```llvm
; 입출력 함수 선언 (위 '입출력 함수' 블록을 그대로 포함)

define i32 @main() {
  ; TODO
  ret i32 0
}
```

`%val`, `%out`처럼 `%`로 시작하는 이름은 함수 안에서 단 한 번만 정의된다.
이를 SSA(Static Single Assignment, 정적 단일 대입) 규칙이라 한다.
`alloca`로 만든 `%x`는 주소 자체가 변하지 않으며, 저장된 내용은 `store`와 `load`로 바꾼다.
고급 언어의 가변 변수는 `alloca` 공간이, 중간 계산 결과는 SSA 레지스터가 담당한다.

### 구현 과제 #1

상수 값을 `@write`에 바로 넘겨 출력한다. `alloca`는 필요 없다.

1. `@main` 안에서 `call void @write(i32 42)`를 작성하고 `42`가 출력되는지 확인한다.
2. 값을 `0`, `-7`로 바꿔가며 결과를 확인한다.

### 구현 과제 #2

상수 값을 `alloca`로 만든 공간에 저장한 뒤 읽어 출력한다.

1. `%x = alloca i32`로 공간을 만들고 그 주소를 `%x`에 저장한다.
2. `store i32 42, ptr %x`로 값을 넣는다.
3. `%out = load i32, ptr %x`로 값을 꺼내 `@write`에 넘긴다.
4. 과제 #1과 결과가 같은지 확인한다.

### 구현 과제 #3

입력받은 값을 변수에 저장했다가 출력한다.

1. `%x = alloca i32`로 공간을 만든다.
2. `%val = call i32 @read()`로 입력을 읽어 `%val`에 받는다.
3. `store i32 %val, ptr %x`로 `%x`에 저장한다.
4. `%out = load i32, ptr %x`로 꺼내 `call void @write(i32 %out)`로 출력한다.
5. `42`, `0`, `-7`을 입력해서 같은 값이 출력되는지 확인한다.

### 구현 과제 #4

1. 기존 구현 과제 #3과 동일하지만, 두 수를 각각 읽어 순서대로 출력하도록 확장한다.
2. `42 0`과 같이 동시에 입력하면 `42`, `0`이 순서대로 출력되어야 한다.
3. 2개 입력을 먼저 완료해야 출력되는 프로그램을 작성해본다. 
   `42`만 입력하고 `0`이 추가 입력되지 않으면 출력되지 않는다.

### 알아 둘 내용

1. `alloca`는 저장 공간의 주소를 반환한다. `%x`는 정수 값이 아닌 주소다.
2. 값을 읽기 전에 반드시 `store`로 넣어야 한다. `alloca`만으로는 초기화되지 않는다.
3. `alloca`는 함수 진입 블록에 모아 두는 것이 관례다.
4. 앞으로 조건문, 반복문에서 가변 상태를 다룰 때도 이 패턴을 그대로 사용한다.

## 산술 연산

두 수를 읽어 덧셈, 뺄셈, 곱셈, 나눗셈 결과를 순서대로 출력한다.

각 연산은 아래 명령으로 수행한다.

```llvm
%sum  = add  i32 %a, %b
%diff = sub  i32 %a, %b
%prod = mul  i32 %a, %b
%quot = sdiv i32 %a, %b
```

```llvm
define i32 @main() {
  %a = call i32 @read()
  %b = call i32 @read()

  ; TODO: 사칙연산 결과를 각각 계산하고 순서대로 출력하세요

  ret i32 0
}
```

`%sum`, `%diff` 같은 이름은 한 함수 안에서 단 한 번만 정의할 수 있다.
이것이 SSA(Static Single Assignment) 규칙이며, LLVM IR은 이 규칙을 언어 차원에서 강제한다.
같은 이름에 두 번 값을 넣으려 하면 SSA 위반으로 컴파일 오류가 난다.
고급 언어에서 `x = x + 1`처럼 같은 변수 이름을 재사용하던 것을 IR에서는 `%x2 = add i32 %x1, 1`처럼 새 이름으로 표현해야 한다.

### 구현 과제 #1

1. `10`과 `3`을 입력하면 `13`, `7`, `30`, `3`이 순서대로 출력되는지 확인한다.
2. `%sum`이라는 이름을 다시 정의하려 하면 어떤 오류가 나는지 확인한다.

### 구현 과제 #2

1. 원래 나머지 연산은 `srem`을 사용하면 구현할 수 있다.
2. 나머지 연산 명령어가 없다 가정하고, `a - (a / b) * b`로 나머지를 구하는 코드를 추가한다.

### 알아 둘 내용

1. 덧셈은 `add`, 뺄셈은 `sub`, 곱셈은 `mul`, 부호 있는 정수 나눗셈은 `sdiv`다.
2. `sdiv`는 소수 부분을 버린다. 이 실습에서 0으로 나누는 경우는 입력에서 제외한다.

## 복합 수식

연산자 우선순위가 있는 수식을 IR로 표현한다.

고급 언어에서 `(a + b) * (a - b)`는 한 줄로 쓸 수 있다.
IR에서는 중간값 각각에 이름을 붙이고 순서대로 나열해야 한다.
우선순위는 명령어의 나열 순서로 표현된다.

```llvm
%tmp1   = add i32 %a, %b   ; 먼저 계산할 것
%tmp2   = sub i32 %a, %b
%result = mul i32 %tmp1, %tmp2
```

```llvm
define i32 @main() {
  %a = call i32 @read()
  %b = call i32 @read()

  ; TODO: (a + b) * (a - b) 를 계산하고 출력하세요
  ;       중간값마다 고유한 이름을 붙이고 순서대로 나열하세요

  ret i32 0
}
```

### SSA가 필요한 이유: 가짜 의존성 제거

명령어 사이의 의존성에는 네 종류가 있다.

| 종류 | 순서 | 예시 | 의미 |
|------|------|------|------|
| RAW (Read After Write) | 쓰기 → 읽기 | `x = 1` 뒤에 `y = x + 1` | 진짜 의존성 |
| WAR (Write After Read) | 읽기 → 쓰기 | `y = x + 1` 뒤에 `x = 2` | 가짜 의존성 |
| WAW (Write After Write) | 쓰기 → 쓰기 | `x = 1` 뒤에 `x = 2` | 가짜 의존성 |
| RAR (Read After Read) | 읽기 → 읽기 | `y = x + 1` 뒤에 `z = x + 2` | 의존성 없음 |

RAW는 앞 명령의 결과를 뒤 명령이 실제로 사용하는 **진짜 의존성**이다.
WAR와 WAW는 값의 흐름과 무관하게 **이름이 같아서** 생기는 **가짜 의존성**이다.
RAR은 같은 값을 여러 번 읽는 것으로, 순서를 바꿔도 결과가 달라지지 않아 의존성이 없다.

아래 코드에서 가짜 의존성이 어떻게 생기는지 보자.

```
x = a + b    ; ①  x에 씀
y = x * 2    ; ②  x를 읽음  →  RAW: ①이 먼저여야 함 (진짜)
x = c + d    ; ③  x에 다시 씀  →  WAR: ②가 읽기 전에 ③이 실행되면 안 됨 (가짜)
z = x + 1    ; ④  x를 읽음  →  RAW: ③이 먼저여야 함 (진짜)
```

③이 x를 다시 쓰는 것은 ①의 x와 의미상 다른 값이다.
이름이 같아서 ②와 ③ 사이에 가짜 의존성이 생길 뿐이다.

SSA에서는 이름을 재사용하지 않으므로 가짜 의존성이 사라진다.

```
x1 = a + b
y1 = x1 * 2   ; RAW: x1 — 진짜 의존성만 남음
x2 = c + d    ; ①②와 이름이 달라 WAR 사라짐
z1 = x2 + 1
```

이제 `x2 = c + d`는 `x1` 관련 명령들과 독립적이다.
컴파일러는 진짜 의존성(RAW)만 추적하면 되므로 명령어 재배치와 최적화가 단순해진다.

### 구현 과제 #1

`(a + b) * (a - b)`를 계산하고 출력한다.

1. `4`와 `1`을 입력하면 `15`가 출력되는지 확인한다.
2. `a * a + b * b`를 IR로 직접 작성하고 `3`, `4`를 입력해서 `25`가 나오는지 확인한다.

### 구현 과제 #2

가짜 의존성을 직접 확인한다. 앞에서 설명한 WAR·WAW 예제를 IR로 구현한다.

```
a, b, c, d 네 수를 순서대로 읽는다
x = a + b      ; ①
y = x * 2      ; ②  RAW(①) — 진짜 의존성
x = c + d      ; ③  WAR(②), WAW(①) — 가짜 의존성
z = x + 1      ; ④  RAW(③) — 진짜 의존성
x, y, z 각각 출력
```

IR에서 `x`는 두 번 나타나므로 `%x1`, `%x2`로 구분해야 한다. 이름이 갈라지면 ②와 ③ 사이의 가짜 의존성이 사라져 두 계산은 완전히 독립적이 된다.

1. `1 2 3 4`를 입력하면 `6`, `8`이 출력되는지 확인한다.
2. IR에서 `%y = mul i32 %x1, 2`와 `%x2 = add i32 %c, %d` 사이에 진짜 의존성이 있는지 확인한다. 두 줄의 순서를 바꿔도 결과가 같다면 독립적인 것이다.
3. 의사코드의 ①②③④ 각 줄이 IR에서 어떤 이름으로 대응되는지, 그리고 가짜 의존성이 어디서 사라지는지 정리한다.

### 알아 둘 내용

1. 괄호를 나타내는 명령은 없다. 먼저 계산할 것을 먼저 쓰고, 그 결과 이름을 다음 연산에 넣으면 된다.
2. 중간값에는 `%tmp1`, `%tmp2`처럼 겹치지 않는 이름을 붙인다.
3. 고급 언어에서 파서가 처리해 주던 연산 순서 결정을 IR에서는 직접 해야 한다.

## 조건문

mod 연산 없이 짝수/홀수를 판별한다. 분기문을 처음 사용한다.

| 명령 | 역할 |
|------|------|
| `%c = icmp eq i32 %a, %b` | `%a == %b`를 비교해 `i1`(1비트 불리언)을 `%c`에 저장 |
| `%c = icmp ne i32 %a, %b` | `%a != %b` |
| `%c = icmp sgt i32 %a, %b` | `%a > %b` (부호 있는 정수 기준) |
| `%c = icmp sle i32 %a, %b` | `%a <= %b` (부호 있는 정수 기준) |
| `br i1 %c, label %A, label %B` | `%c`가 참이면 블록 A, 거짓이면 블록 B로 분기 |
| `br label %X` | 무조건 블록 X로 이동 |

분기가 합류하는 블록에서 결과를 사용하려면, 각 분기 안에서 `alloca` 공간에 `store`하고 합류 지점에서 `load`한다.

짝수 판별 조건: `(n / 2) * 2 == n`이면 짝수.

```llvm
define i32 @main() {
  %n      = call i32 @read()
  %result = alloca i32

  ; TODO: (n / 2) * 2 == n 조건을 계산하고
  ;       %cond 에 icmp 결과를 저장한 뒤 분기하세요

  br i1 %cond, label %even, label %odd

even:
  store i32 0, ptr %result
  br label %end

odd:
  store i32 1, ptr %result
  br label %end

end:
  %out = load i32, ptr %result
  call void @write(i32 %out)
  ret i32 0
}
```

### 구현 과제 #1

짝수/홀수 판별기를 구현한다.

1. `0`, `1`, `2`, `-3`, `-4`를 각각 입력해서 `0`, `1`, `0`, `1`, `0`이 출력되는지 확인한다.
2. 조건을 `icmp ne`로 바꾸면 결과가 반전되는지 확인한다.

### 구현 과제 #2

두 수를 입력받아 큰 수를 출력하는 프로그램을 작성한다.

1. `icmp sgt`로 두 수를 비교하고, 블록 구조는 과제 #1과 같은 방식으로 구성한다.
2. `3 7`을 입력하면 `7`, `5 2`를 입력하면 `5`가 출력되는지 확인한다.
3. 두 수가 같을 때 어느 값이 출력되는지 확인하고, 의도한 동작인지 점검한다.

### 알아 둘 내용

1. `icmp`의 비교 결과는 `i1`이다. 산술 연산에 직접 쓸 수 없고 `br`의 조건으로만 사용한다.
2. 각 기본 블록은 반드시 `br` 또는 `ret`으로 끝나야 한다. 블록 중간에서 다른 블록으로 넘어가는 명령은 없다.
3. 레이블(`even:`, `odd:`, `end:`)은 기본 블록의 시작을 표시한다.
4. 분기가 합류하는 블록에서는 어느 경로를 거쳐 왔든 `alloca` 공간에 올바른 값이 들어 있다.
5. LLVM IR에는 분기 합류를 위한 `phi` 명령이 따로 있다. `phi`는 "어느 블록에서 왔느냐"에 따라 값을 선택해 SSA 레지스터 하나로 받는 명령으로, `alloca`/`store`/`load` 없이도 합류 지점에서 값을 다룰 수 있다. 이 실습에서는 `phi`를 사용하지 않는다. `alloca`/`store`/`load`로 같은 구조를 직접 구현해 보는 것이 목적이다.

## 반복문

반복문으로 `n!`을 계산한다. 루프의 기본 블록 구조를 익힌다.

가변 상태(누산기, 카운터)는 `alloca`로 관리한다.
매 반복마다 `load → 계산 → store`로 상태를 갱신한다.

```llvm
define i32 @main() {
  %n   = call i32 @read()
  %acc = alloca i32
  %i   = alloca i32

  ; TODO: 누산기와 카운터 초기값을 store 하세요

  br label %loop

loop:
  ; TODO: 현재 값을 load 하고 i <= n 조건을 검사하세요
  br i1 %cond, label %body, label %end

body:
  ; TODO: acc = acc * i, i = i + 1 을 계산하고 store 하세요
  br label %loop

end:
  %result = load i32, ptr %acc
  call void @write(i32 %result)
  ret i32 0
}
```

### 구현 과제 #1

팩토리얼을 계산한다.

1. `0`을 입력하면 `1`, `5`를 입력하면 `120`이 출력되는지 확인한다.
2. 반복문이 멈추지 않는다면 조건에 쓰이는 값이 실제로 갱신되는지 `write`를 추가해서 확인한다.

### 구현 과제 #2

`1`부터 `n`까지의 합을 구하는 프로그램을 작성한다.

1. `%acc`와 `%i`의 초기값, 갱신 방식이 팩토리얼과 어떻게 달라지는지 비교하면서 작성한다.
2. `5`를 입력하면 `15`가 출력되는지 확인한다.

### 알아 둘 내용

1. `%cur_i`, `%new_i`처럼 IR 레지스터는 여전히 한 번씩만 정의된다. 루프를 돌아도 이름 충돌이 없는 이유는, 상태가 레지스터가 아닌 `alloca` 공간에 저장되기 때문이다.
2. `icmp sle`는 부호 있는 정수로 `<=`를 비교한다.
3. 반복 변수 갱신을 빠뜨리면 무한 루프가 된다.

## 함수

조건문과 반복문으로 작성한 로직을 각각 함수로 분리하고 `@main`에서 호출한다.

```llvm
define i32 @is_odd(i32 %n) {
  ; TODO: 조건문 실습의 로직을 함수로 옮기세요
  ret i32 0
}

define i32 @factorial(i32 %n) {
  ; TODO: 반복문 실습의 로직을 함수로 옮기세요
  ret i32 0
}

define i32 @main() {
  %n      = call i32 @read()
  %parity = call i32 @is_odd(i32 %n)
  %fact   = call i32 @factorial(i32 %n)
  call void @write(i32 %parity)
  call void @write(i32 %fact)
  ret i32 0
}
```

### 구현 과제 #1

`@is_odd`를 구현한다. 조건문 실습에서 작성한 짝수/홀수 판별 로직을 함수 본문으로 옮긴다.

1. `4`를 입력하면 `0`, `7`을 입력하면 `1`이 출력되는지 확인한다.

### 구현 과제 #2

`@factorial`을 구현한다. 반복문 실습에서 작성한 팩토리얼 로직을 함수 본문으로 옮긴다.

1. 누산기와 카운터를 함수 안의 `alloca`로 선언하고, 매개변수 `%n`을 반복 조건에 사용한다.
2. `5`를 입력하면 `1`과 `120`이 차례로 출력되는지 확인한다.

### 구현 과제 #3

1. `@is_odd`에서 `alloca`/`store`/`load` 대신 각 분기 안에서 바로 `ret`으로 반환하도록 수정한다.
2. 두 수를 인자로 받아 더 큰 값을 반환하는 `@max` 함수를 직접 작성하고 `@main`에서 호출한다.

### 알아 둘 내용

1. `define i32 @함수명(i32 %인자)` — 반환형과 매개변수를 선언한다.
2. `ret i32 %값` — 값을 반환하고 함수를 종료한다.
3. `call i32 @함수명(i32 %인자)` — 함수를 호출하고 반환값을 받는다.
4. 각 함수 안의 레이블은 함수 범위 안에서만 유효하다. 다른 함수에서 같은 레이블 이름을 써도 충돌하지 않는다.
5. 매개변수를 가변 변수처럼 써야 할 때는 `alloca`로 공간을 만들고 전달받은 값을 `store`한 뒤 사용한다.

## 재귀 호출

팩토리얼 계산을 재귀 호출로 다시 구현한다.

반복문 버전에서는 `alloca`로 상태를 직접 관리했다.
재귀 버전에서는 호출마다 스택 프레임이 쌓이고, 각 호출의 인자와 반환값이 상태를 전달한다.

```llvm
define i32 @factorial(i32 %n) {
  %cond = icmp eq i32 %n, 0
  br i1 %cond, label %base, label %recurse

base:
  ret i32 1

recurse:
  ; TODO: n-1 을 계산하여 재귀 호출하고, 결과에 n 을 곱해 반환하세요
  ret i32 0
}

define i32 @main() {
  %n    = call i32 @read()
  %fact = call i32 @factorial(i32 %n)
  call void @write(i32 %fact)
  ret i32 0
}
```

### 구현 과제 #1

`@factorial`을 재귀로 구현하고 결과를 검증한다.

1. `0`을 입력하면 `1`, `5`를 입력하면 `120`이 출력되는지 확인한다.
2. 함수 실습의 반복문 버전 `@factorial`과 같은 입력에 대해 결과가 동일한지 비교한다.

### 구현 과제 #2

`@is_odd`를 재귀로 구현한다. `n`이 0이면 짝수, `n`이 1이면 홀수를 기저 조건으로 삼고, 그 외에는 `is_odd(n - 2)`를 재귀 호출한다.

1. 음수 입력은 제외하고 `0`, `1`, `2`, `5`, `6`을 입력해서 `0`, `1`, `0`, `1`, `0`이 출력되는지 확인한다.
2. 반복문 기반의 `@is_odd`와 결과를 비교한다.

### 알아 둘 내용

1. 재귀 호출은 일반 함수 호출과 문법이 동일하다. 자기 자신을 `call`하면 된다.
2. 호출마다 새 스택 프레임이 생기므로 `%n`, `%n1`, `%sub_ret` 같은 이름이 각 호출에서 독립적으로 존재한다.
3. 기저 조건에서 반드시 재귀를 멈춰야 한다. 빠뜨리면 스택이 가득 찰 때까지 실행된다.
4. 반복문 버전과 재귀 버전은 결과가 같지만 IR 구조가 다르다. 반복문은 `alloca`로 상태를 관리하고, 재귀는 호출 스택이 상태를 담는다.
